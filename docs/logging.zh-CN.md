# 日志说明

从现在开始，图片生成、图片编辑和提示词优化链路会为同一次请求生成两份日志，方便运维人员和 AI 排障各取所需。

## 目录结构

```text
logs/
  ops/  # 给中国运维人员阅读的中文摘要日志
  ai/   # 给 AI / 开发排查问题的结构化 JSONL 日志
```

两份日志使用相同文件名前缀，例如：

```text
logs/ops/image-20260428-102000-abc123def456.log
logs/ai/image-20260428-102000-abc123def456.jsonl
```

其中 `abc123def456` 是本次请求的 `trace_id`，可以用来关联两份日志。

## 运维日志

运维日志位于 `logs/ops`，每行是中文摘要，适合直接打开查看或发给一线运维定位问题。

示例：

```text
[2026-04-28T10:20:00+0800] [abc123def456] +0ms 请求开始：类型=generation；接口=/v1/images/generations；模型=gpt-image-2；数量=1；提示词长度=18；提示词预览=一只橘猫坐在窗台上
[2026-04-28T10:20:03+0800] [abc123def456] +3120ms 请求成功：耗时=3120ms；结果数=1；已保存图片=[{"file_name":"image.png","file_size":42}]
```

优先关注：

- `请求失败` / `参数校验失败`：直接看本行的 `错误`、`字段`、`状态码`。
- `上游请求尝试失败`：看 `上游路径`、`尝试次数`、`状态码` 和 `错误`。
- `等待重试上游请求`：说明后端正在自动重试，不一定需要人工介入。
- `图片文件已保存`：可根据 `文件路径` 检查图片是否已经落盘。

## AI 排障日志

AI 排障日志位于 `logs/ai`，每行是一个 JSON 对象，保留完整事件字段和结构化数据，适合复制给 AI 或开发人员分析。

示例：

```json
{"ts":"2026-04-28T10:20:00+08:00","elapsed_ms":0,"trace_id":"abc123def456","event":"request.start","kind":"generation","prompt":"一只橘猫坐在窗台上","prompt_length":9}
```

排障时建议提供：

- 对应 `logs/ops` 中出错请求的前后 20 行。
- 同名 `logs/ai/*.jsonl` 文件全文。
- 用户请求的大致时间、接口路径和是否经过上游重试。

## 上下文管理

排障和后续改造时优先使用 `codex-agent-mem` MCP 读取项目上下文，避免重复确认历史决策。当前运行环境中的 MCP 连接为只读模式，如果项目未登记或连接中断，应在交付说明中明确记录，并把关键设计同步到本文档。
